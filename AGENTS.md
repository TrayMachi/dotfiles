# Dotfiles Repository

## Sync Safety

- Repository mirrors `~/.config/{fish,hypr,niri,opencode,fastfetch}` and `~/.agents` into matching top-level directories.
- `make` defaults to `backup`: it copies system config into repository with `rsync --delete`. Never run `make`, `make backup`, or a `backup-*` target unless system state should replace repository state.
- `restore-*` copies repository state into system config with `rsync --delete`; use `make diff-<component>` first. Despite their names, `confirm-restore-*` targets skip confirmation entirely.
- Prefer one component target (`diff-niri`, `backup-fish`, etc.) over broad `diff`, `backup`, or `restore` targets.
- Keep credentials out of tracked files. `fish/conf.d/secrets.fish` is intentionally ignored; `opencode/opencode.json` references secrets through `{env:...}` placeholders.

## Configuration Boundaries

- Hyprland starts at `hypr/hyprland.lua`. Treat `hypr/hyprland/` as imported defaults and put personal overrides in `hypr/custom/` where the entrypoint loads them.
- `hypr/monitors.lua` and `hypr/monitors.conf` are generated by `nwg-displays`; regenerate rather than hand-edit them.
- Niri starts at `niri/config.kdl` and includes `niri/noctalia.kdl`; validate both through the entrypoint.
- `agents/.skill-lock.json` and `agents/.iris/installed.json` record installer-managed skills. Change installed skills through their installer rather than editing metadata or vendored copies by hand.
- Under `opencode/`, also follow `opencode/AGENTS.md`; shell commands must use RTK as specified there.

## Focused Checks

- No repository-wide test or lint task exists. Validate only changed config types.
- Niri: `niri validate -c niri/config.kdl`
- Fish: `fish -n <changed-file.fish>`
- Lua syntax: `luac -p <changed-file.lua>`
- Strict JSON: `jq empty <changed-file.json>`; do not use this for JSONC files such as `fastfetch/config.jsonc`.
